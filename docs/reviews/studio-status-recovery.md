# Studio status reconciliation and retired budget continuation

A status request that never settles previously froze the screen at its last response. The observer now times out after 12 seconds, aborts the read, retries after 10 seconds, and reconciles on focus, visibility and reconnect. A late result cannot overwrite a newer one. These are read-only requests, never generation retries. Real unsaved edits remain protected; applied server snapshots use the same matter normalization and B10 fallbacks as dirty detection.

Unavailable delivery offers a real status refresh instead of a reference to a nonexistent support team. It does not promise that a permanently failed operation will finish merely by refreshing. Existing available files retain their observations and remain distinct from approval.

Historical budget admission failures can continue once under the submission lock when the cap is disabled, sources still match, a checkpoint exists, usage is known and the refused provider operation demonstrably never started. The recent-job worker sweep and the authenticated Continue action use the same enqueue guards. No new extraction, cursor reset, method refill or receipt deletion. Final-review budget continuation retains its separate existing policy. Unknown provider outcomes remain protected against duplicate generation.

Validation covers hung connections, late responses, terminal-to-completed polling, disposal, actual UI action dispatch, unknown outcomes, changed sources and repeated enqueue. This addresses delivery visibility and budget admission, not editorial quality acceptance. It does not claim that every provider failure can be recovered automatically.
