# Profile entities and pre-review recovery — v1.0.69

A profile source sentence can contain several client identities or professional bodies. v68 represented it as one identity; its strict literal checks rejected legitimate multi-entity sentences. Coverage now permits separate atomic entity records for the same original source unit. Every record retains its complete original quote and its own privacy basis. The independent obligation sees all records and restriction sources; output-only repair gives each record a distinct key so one entity cannot overwrite another. Single-entity historical records retain their existing keys and checks.

A second gap stopped complete prose before field review. The initial contract repair uses an initial attempt and a bounded residual; the delivery continuation had required counters created only by the later semantic review. It now recognizes the actual residual receipt for every failed field, without manufacturing counters or allowing another contract repair. Complete source-current, privacy-checked prose proceeds through independent field review, then the existing Audit and exact-Word review. Internal findings remain observations and cannot become an approval. New findings, incomplete content, unknown usage and actual privacy failures do not inherit this exception. Resolved local observations are removed only after revalidation.

The existing one-time recovery action also accepts that receipt for a previously stopped job, keeping its source hash, job, checkpoint and full token ledger. New jobs traverse the corrected boundary automatically. No new model, budget expansion or universal extra pass is introduced.

Validation: synthetic multi-entity and separate restriction tests; output-only delta identity isolation; the full local-contract-to-field-review transition without a third repair; combined local and semantic observations; rejected incomplete, stale and unknown-usage continuations. Private replay of the captured failed checkpoint schedules field review with unchanged prose and zero provider calls. This is evidence of recovery routing, not a successful production run or proof of final document quality. Production continuation and the comparison against the frozen quality reference remain separate validation steps.
