# v1.0.63 — Source-complete review and bounded continuation

The early institutional reviewer received selected matters but omitted confirmed department heads, original profiles and original institutional narratives. It could reject a supported leadership claim while repair preserved that same claim from the fuller source view. Institutional review now reuses the original development source view, alongside the selected matters. It distinguishes practice leadership, matter leadership and partner seniority. Generated drafts remain separate from source evidence; context changes invalidate the affected receipts.

A narrowly identified earlier context failure can receive one source-complete reconsideration. Prior method counts and usage remain intact. Legacy targeted repairs may migrate once to source reconstruction, preserving their original trace; an unused first-method residual takes precedence. Parent/child field addresses share method counts, so changing a candidate target to its BIO cannot refresh recovery rights. Unknown usage, unanswered source questions and repeated methods remain protected.

An explicit owner-authorized capacity event can increase an existing job's token ceiling independently of a one-final-review exception. It does not reset spend, repair methods, review failures or unknown provider calls. A job stopped solely for capacity can resume its saved final stage once per authorized ceiling, with unchanged sources and result binding, rather than starting extraction or selection again. Legacy final-stage recovery migrates a recorded single targeted pass into its actual field counters; otherwise the old global limit would immediately stop new field repairs. Ambiguous multiple-pass histories remain ineligible. No production allowance changes are made by this release itself.

The delivery panel presents its next action once, keeps system findings in expandable details and avoids duplicate continuation buttons inside the panel. The source-information badge requests action only when preparation inputs are actually missing. The sidebar distinguishes current saved internal drafts and selection from approved editor content; changed sources or local edits suppress stale progress. A user-owned source question is not given a premature system-retry button. Automatic continuation is described only while work is actually queued or running; this change does not claim every terminal failure is recoverable.

Validation: 764 Python tests; 544 Node tests passed and one existing skip; TypeScript passed. Offline replays of saved checkpoints verify complete institutional context and legacy field migration without generation, source edits, usage resets or approving prose. These checks do not establish a new approved Word pair or customer acceptance. Publication and native continuation results are recorded separately in the private control.
