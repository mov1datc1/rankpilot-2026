# v1.0.61 — Source-bound field review and recoverable editorial work

A source-confirmed team member could pass early BIO validation while the final reviewer rejected the omitted participation. The development contract now distinguishes participation from individually achieved legal work, and drafting, validation, typed repair and review share that obligation. A membership correction can append only the fixed original evidence and a public participation passage; it cannot promote the lawyer or invent leadership.

Development now checks the final review's field obligations before constructing the Audit. Each bounded group is persisted independently. Unchanged source/output/policy checks are reused; an edit invalidates the affected checks. Signed receipts can suppress duplicate final BIO checks only when the actual exported Word BIO matches. Matter narratives, public institutional fields, privacy, source-register comparisons, cross-document consistency and independent final approval remain required.

A failed field receives a targeted correction, then source reconstruction if needed. Early and final repairs share a field counter. A new field is no longer stopped simply because two earlier document reviews occurred; the cumulative job budget and unknown-provider-outcome guard still apply. Residual requests belong to the same method, and their queues survive a pre-call admission failure. A bound field address takes precedence over coincidentally repeated wording elsewhere.

The trusted worker supplies the remaining generation allowance. The engine uses the Responses input-count endpoint with the actual structured request, reserves its configured maximum output, and checks before starting generation. Calls in one stage share the remaining allowance; unknown outcomes block further calls. An unavailable count gets at most one worker retry and cannot approve documents. This prevents starting an unaffordable request; it does not guarantee that every portfolio fits the current budget. The SDK and model settings remain unchanged.

The interface derives the next action from real job state: wait for scheduled work, answer a source question, continue an eligible saved attempt, download approved documents, or copy the attempt reference for technical recovery. A stopped attempt never promises an automatic restart.

Historical jobs whose structured case-plan or institutional bindings were omitted from the residual queue can explicitly continue once after a software fix. Eligibility requires unchanged sources, known usage, remaining budget, validated selection and proof that those failed paths were never retried. This takes precedence over an unpaid validator-only recheck that would simply rediscover the unresolved correction. It keeps the same job, source and consumption, and does not reactivate exhausted or unknown-outcome jobs.

Validation: 758 Python tests, 529 Node tests passed with one pre-existing skip, and TypeScript. Coverage includes serialized field review→repair→recheck, shared attempt limits, lost/stale state, signed receipt binding, actual DOCX worker integration with simulated model responses, authentication and pre-call budget boundaries. A saved rejected proposal replay now identifies its two missing participation obligations before final review. A synthetic request to the real OpenAI input-count endpoint succeeded; no document generation or private sources were used for that compatibility check.

These checks establish code-path behavior, not the semantic quality of a new client delivery. Publication, a fixed native Builder run and comparison of its actual Word pair against prior outputs and feedback must be recorded separately. Do not interpret this release as a new approved pair or customer acceptance.
