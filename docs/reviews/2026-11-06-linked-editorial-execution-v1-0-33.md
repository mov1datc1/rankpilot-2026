# Linked editorial execution v1.0.33

A source-backed career biography and a service list could satisfy local development checks without developing the individual's personally attributed legal contribution. The shared institutional plan could also be present internally without an explicit link to each public B10/C2 argument. A later repair could then remove an unsupported promotional clause while breaking its previously retained profile quotation.

Newly generated proposals use `linked-editorial-execution-v1`. Nominated candidates bind distinct supporting mandates to their original source and literal B9 passages (two when multiple supporting mandates exist, one when there is only one). Institutional arguments link to their own B10 and C2 passages; missing, foreign-field and duplicate-copy proofs fail local validation. The exact-file reviewer independently assesses each personal mandate against its original evidence. These bindings do not certify the semantic quality of a paragraph by themselves.

Missing confirmed department-head wording is detected before the full Word review, without treating partnership or leading an individual matter as headship. A bounded biography correction can update its affected profile/output links while retaining original career facts, source bindings, ranking decisions and unrelated fields. Rejected wording is checked in the biography rather than in its immutable historical source quote. Public prose corrections refresh dependent institutional output links in the same repair.

Candidate repairs receive their own attributed eligible sources, evidence needed to remove invalid attributions, and a compact public-entity restriction register. They no longer repeat every unrelated matter narrative per biography. An offline captured-target comparison reduced serialized request bytes by 81%; this is a payload measurement, not a claim about billed token savings.

The development checkpoint contract changes while the selection contract remains stable. A fictional checkpoint produced by the preceding implementation verifies that selection, review counts and known usage survive the upgrade, while old development is replaced. Artifact review advances to version 22; the renderer stays at 21. Existing retry allowances and cumulative ledger are unchanged. No stopped job is automatically revived by this release.

An unavailable final diagnostic is presented as an internal review task rather than asking the user to change source data. A separate genuine source-confirmation request remains visible.

Validation: 540 Python tests, 492 Node passes and one skip, and TypeScript checks pass. These use fictional fixtures and unpaid captured-target inspection. A new end-to-end production trial and comparison of its actual Word pair are still required. Private sources, provider responses, legal documents and comparison evidence are excluded from publication.
