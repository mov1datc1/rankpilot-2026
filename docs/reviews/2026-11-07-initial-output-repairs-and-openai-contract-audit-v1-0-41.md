# Initial output repair scope and OpenAI contract audit v1.0.41

An initial B9 output-quotation fault could still request a complete Candidate even when its original profile units, personally attributed source bindings, supporting evidence and category were valid. The immutable BiographyOutputDelta previously covered later BIO edits and cleanup, but not this initial route. This exposed already valid metadata to unnecessary model transcription.

Initial repairs now use the same typed output-only delta only when faults are exclusively missing literal BIO output quotes, the known source person and all original support bindings are valid, and category/internal fields need no correction. Source, attribution, duplicate support, missing role, primary-link or category faults retain their broader repair route. The fixed primary append from v1.0.40 remains separate. Whole-Candidate prompt instructions are explicitly restricted to the full schema; immutable delta instructions no longer conflict with them. No source, category, recommendation, identity or nomination changes are permitted by the narrowed route.

Validation covers native delta generation shape, one-call local repair, immutable original data, and preservation of full repair for invalid evidence/categories. The captured mixed repair now exposes three BIO delta targets, including the existing typed primary append. Native SDK strict-schema serialization checks pass for development and mixed repair. These are offline checks, not new provider generation or final document approval.

Official OpenAI documentation confirms that Structured Outputs constrain shape but can still contain content mistakes, and recommends keeping schema and program types aligned. Reasoning and visible output share the output allowance; incomplete responses must remain identifiable. Sources: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [reasoning models](https://developers.openai.com/api/docs/guides/reasoning), [Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra), [Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol).

Offline serialization of pinned SDKs confirms Responses API reasoning/output parameters and zero SDK retries. Previously retained provider responses were completed with output below their allowance. No evidence establishes that this observed failure requires larger models or higher token limits; model, reasoning defaults, SDK versions, budgets and retry limits remain unchanged. The local factory temperature setting is omitted by the pinned SDK on these reasoning calls; it should not be interpreted as deterministic output. Further quality evaluation remains required.
