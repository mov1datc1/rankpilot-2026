# Evidence execution, source questions and draft preservation v1.0.28

The latest frozen acceptance exposed three separate paths: material scale was omitted from confidential matter prose although it survived in internal evidence; a question about an unchanged source value entered a generated-prose locator and prevented already-located corrections; resetting a completion cache marker invalidated the preserved draft pair and caused the download endpoint to reconstruct different status text.

These belong to previously reported families of evidence loss, source/output confusion and inconsistent downloads. The precise locator failure and cache-marker invalidation were reproduced from the saved failed state. This does not establish that every manifestation was caused by the latest release, or that older and newer download failures had the same implementation cause.

Development v4 now requires an independent, own-source, field-bound execution proof for every selected matter narrative. The reviewer must assess material legal work, outcome, attribution and scale in the actual narrative; internal evidence quotes cannot substitute for their execution. Confidential E narratives preserve private metrics, subject to explicit restrictions; public sections retain their privacy requirements. Missing or foreign proofs remain invalid diagnostics, not approval.

An unchanged source-value question with an exact binding to that matter's value is classified as user input before a prose locator can be purchased. Its action asks what the amount represents, including an unavailable option, and explains how to continue. A generated or invented amount remains a RankPilot correction. Historical cached findings are checked again at the repair boundary. Independent generated corrections can run once before pending source input, without buying another artifact review. Repeated clicks on that unchanged waiting state preserve the job and ledger rather than buying a new repair allowance.

Draft-byte binding excludes only the completion cache marker, retaining source and generated-content invalidation and byte-integrity checks. Legacy drafts are recoverable only when the exact original binding is reproduced by restoring their own revision marker. No source, prose, status, approval or prior failed verdict is modified. Exact preserved draft bytes remain explicitly unapproved.

Validation: 516 Python tests; 485 Node passes and one skip; TypeScript and production build pass. Private read-only offline replay locates four generated corrections without a locator/model call, separates one source-value question, creates 18 narrative execution obligations, and recovers both previously reviewed draft hashes exactly. Source and E8 edits invalidate those bytes. Public fixtures are fictional. No extraction, paid model call, source edit, budget extension or failed-job restart was performed for this repair. These results validate the reproduced routing and binding faults, not a new autonomous editorial acceptance or universal output quality.
